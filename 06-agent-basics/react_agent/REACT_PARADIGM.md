# ReAct (Reasoning + Acting) 范式：赋予 AI "手和脚"

## 1. 什么是 ReAct 范式？
在传统的 Prompt 工程中，大模型就像一个“闭门造车”的谋士，只能基于大脑里的固有知识被动回答问题。
**ReAct = Reasoning (思考) + Acting (行动)**。
它由普林斯顿大学和 Google 于 2022 年联合提出。ReAct 的核心思想是：让大模型不仅要“想”，还要去“做”。通过赋予大模型一套“工具箱”（外部 API、数据库查询、计算器等），让模型在遇到知识盲区时，自己去调用工具获取答案。

## 2. 核心运转流程 (The Loop)
一个标准的 ReAct Agent 运行时，脑海里会不断重复以下经典循环，直到得出答案：

1.  🤔 **Thought (思考)**：分析当前用户的问题和已经获取到的线索，思考下一步该怎么做。
2.  🛠️ **Action (行动)**：决定从工具箱中选取某一个特定工具，并生成对应的执行参数。
3.  👀 **Observation (观察)**：外部程序（由你的代码接管）物理执行这个工具，并将返回的客观结果告知大模型。
4.  🔄 **回到 Thought**：大模型根据拿到的“观察结果”，再次思考下一步是继续用工具，还是信息已经充足可以总结答案了。
5.  🏁 **Finish (结束)**：输出最终答复给用户。

## 3. LangGraph 中如何实现？
在现代 AI 工程中，我们通常使用 **LangGraph**。LangGraph 能够将上述的 ReAct 循环具象化为一个带有状态的流程图（StateGraph）：
*   **节点 A (Agent)**：负责调用大模型执行 Thought 和产生 Action 意图。
*   **节点 B (Tools)**：如果节点 A 产生了 Action，流程会路由到节点 B，物理执行 Python 函数，获取 Observation。然后流程强制**回流**到节点 A。
*   只有当节点 A 认为不需要再调用工具时，整个图的执行才抵达终点结束。

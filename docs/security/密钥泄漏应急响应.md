# AgentForge 密钥泄漏应急响应手册

> 依据：本项目安全红线第 1 条「严禁提交密钥、证书或敏感数据」。
> 触发条件：`tools/secret_scan.py` 命中、GitHub Secret Scanning 告警、或人工发现凭据进入版本库。

## 0. 黄金原则（顺序不可颠倒）

**先轮换失效，再清理痕迹。**

只要凭据曾进入任何被推送过的仓库，就必须视为已泄露——攻击者可通过 fork、缓存、CI 日志、页面快照还原。**清理 git 历史无法挽回已暴露的密钥，唯一有效的止损动作是让旧凭据失效。**

## 1. 五分钟止损（发现即执行）

1. **确认凭据是否已到达远端**：`git log --all --oneline -- <文件>` 与 `git branch -r --contains <commit>`。若只在本地分支，处置压力显著下降，但仍须轮换（本地副本、worktree、备份都可能外流）。
2. **到各平台吊销 / 重置**对应凭据（见第 2 节清单）。
3. **本地替换**：更新 `.env`（该文件已在 `.gitignore`，禁止入库）。
4. 若确认已推送到远端且仓库对外可见：**立即轮换，且不要指望删库或改历史来兜底**。

## 2. 本项目涉及凭据的轮换清单

| 凭据 | 位置 | 轮换动作 |
|---|---|---|
| `PRIMARY_API_KEY` | 通问 LLM 平台控制台 | 重新签发 API Key，作废旧 Key |
| `FALLBACK_API_KEY` / `OPENAI_API_KEY` | DeepSeek 开放平台 | 重新签发，作废旧 Key |
| `LANGCHAIN_API_KEY` | LangSmith 控制台（`lsv2_` 前缀） | 重新签发 API Key |
| `JWT_SECRET` | 本地 / 部署密钥管理 | 改为新随机值（≥32 字符），**旧值失效会导致存量会话全部下线，需与发布窗口对齐** |
| `APP_SECRET`、`AGENT_AUTH_SECRET` | 本地 / 部署密钥管理 | 同上，重新生成随机值 |
| `POSTGRES_PASSWORD`、`DATABASE_URL` 口令 | 数据库实例 | `ALTER USER aiuser WITH PASSWORD '<新口令>'`，同步更新所有部署环境 |
| `MYSQL_URI` 口令 | MySQL 实例 | 同上，重置对应用户口令 |
| 云厂商 AK/SK（若后续引入） | 云控制台 | 禁用旧 AK，新建并最小权限授权 |

生成随机密钥建议：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 3. 仓库侧处置

### 3.1 泄漏仅存在于本地分支（未推送）

优先级最低，做两件事即可：

```bash
# 1) 备份引用（万一还需要旧历史，可从这个包恢复）
git bundle create /tmp/agentforge-legacy-backup.bundle --all

# 2) 删除含泄漏提交的本地分支引用，再清理悬空对象
git branch -D legacy-history
git for-each-ref --format='%(refname)' refs/heads | grep '^refs/heads/subagent-' | xargs -n1 git branch -D
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

### 3.2 泄漏已推送到远端

收紧权限后按序执行（必须先完成第 2 节轮换）：

```bash
# 方案 A：git-filter-repo（推荐，需 pip install git-filter-repo）
git filter-repo --path .env --invert-paths --force

# 方案 B：BFG
# java -jar bfg.jar --delete-files .env

git push origin --force --all
git push origin --force --tags
```

注意事项：

- **必须通知所有协作者**：force push 后本地旧历史会冲突，需 `git fetch --all && git reset --hard origin/main`。
- 清理完成后强推仍可能残留：GitHub 的缓存、Pull Request 的旧提交快照、fork 副本。这正是「轮换优先于清理」的原因。
- 通知 GitHub 支持协助清理缓存引用（对企业私有仓库可提交工单）。

## 4. 防复发机制（已落地）

| 层级 | 机制 | 位置 |
|---|---|---|
| 提交前 | 离线指纹扫描暂存区，命中即阻断提交 | `.githooks/pre-commit` 第 0 步 → `tools/secret_scan.py --staged` |
| 持续集成 | 全量 git 历史 + 工作区双扫描，命中即失败 | `.github/workflows/ci.yml` 的 `Secret Leak Guard` 作业 |
| 忽略规则 | `.env.*`、私钥、云凭据、`*.tfvars` 等一律不入库 | `.gitignore` 第 8 节 |
| 模板约束 | `.env.example` 只放占位符，禁止真实值 | `.env.example` |
| 规范约束 | 五大安全红线 + MR 核验清单 | `.cursor/rules/security-standards.mdc` |

本地启用提交钩子（新克隆仓库后需执行一次）：

```bash
git config core.hooksPath .githooks
chmod +x .githooks/pre-commit
```

## 5. 扫描器使用说明

```bash
python3 tools/secret_scan.py            # 扫描当前工作区
python3 tools/secret_scan.py --staged   # 仅扫描暂存区（pre-commit 调用）
python3 tools/secret_scan.py --history  # 扫描全部 git 历史（CI 调用，耗时较长）
```

规则覆盖：OpenAI/DeepSeek `sk-` 密钥、Anthropic `sk-ant-`、AWS `AKIA/ASIA`、Google `AIza`、GitHub `ghp_` 等令牌、Slack 令牌、PEM 私钥块、JWT、硬编码口令、带口令的数据库连接串。

误报处理：把占位符写成 `your_xxx_here`、`<your-key>`、`${ENV_VAR}`、`change_me` 等形态即可命中白名单；确属教学样例的，在 `tools/secret_scan.py` 的 `ALLOWLIST_PATTERNS` 中补充**精确**规则，禁止放宽为宽泛匹配。

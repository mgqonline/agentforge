# 安全开发检查清单.md
> 适用：代码MR评审、版本上线安全准入、季度安全巡检
> 规则：任意【阻断项】不通过 → 禁止合并/禁止发布；告警项需要记录风险并评估，高风险同样阻断上线。

## 1. 密钥与敏感信息检查【阻断项】
> 对应红线：严禁提交密钥、证书或敏感数据

- [ ] 代码仓库、配置文件、注释中**不存在硬编码密钥、AK/SK、数据库密码、私钥证书、token、账号密码**
    - 检查方法：全局代码检索、git历史扫描、配置文件扫描
    - 失败判定：检出任何明文敏感凭证 → 阻断MR
- [ ] 敏感配置全部使用环境变量 / 密钥托管中心，不存于代码库
- [ ] 日志输出不会打印完整密钥、证书、敏感凭证（脱敏处理）
- [ ] 本地开发配置文件（.env等）已加入.gitignore，不会被提交

## 2. 数据库访问安全检查【阻断项】
> 对应红线：严禁绕过权限直改数据库

- [ ] 所有数据库访问（读/写）均前置身份校验、会话校验、数据权限校验
    - 检查方法：检索数据库调用入口，确认无跳过权限校验的分支
- [ ] 不存在直接拼接用户输入的SQL（已使用参数化查询）
- [ ] 不存在绕过权限校验的后门SQL、超级账号直连逻辑
- [ ] 数据库账号最小权限原则，应用账号不持有DROP/ALTER等高权限

## 3. 代码与依赖安全检查
- [ ] 第三方依赖无高危CVE漏洞（依赖扫描工具验证）
- [ ] 废弃代码、调试后门代码已删除，不注释遗留后门接口
- [ ] 生产环境无调试后门接口、无万能绕过token
- [ ] 输入参数统一做类型、长度、范围校验

## 4. 日志与审计安全检查
- [ ] 安全事件、拦截事件完整审计日志，携带session_id链路追踪
- [ ] 日志不记录用户隐私明文（身份证、手机号等）
- [ ] 日志留存时长满足审计要求，日志不可随意篡改
- [ ] 阻断类事件告警可触达安全/负责人

## 5. 输入输出与注入防护检查
- [ ] 用户原始输入经过Pre-Hook安全校验，检测提示词注入、越狱指令
- [ ] LLM生成SQL经过注入检测，危险SQL拦截
- [ ] 工具调用参数经过Schema/Pydantic校验
- [ ] 返回结果做数据脱敏、异常数据检测

## 6. Agent / Skill 安全专项检查【阻断项】
> 映射系统五大强制安全红线，MR必须逐项核验

### 6.1 密钥、证书、敏感数据
- [ ] Skill、Hook代码中**无硬编码密钥、证书、私钥、AK/SK、数据库密码**
    - 检查方式：全局检索代码、单元测试、配置文件
    - 不满足：阻断MR

### 6.2 数据库权限校验
- [ ] 不存在绕过权限校验直接修改数据库的逻辑
- [ ] 所有数据库操作必须经过权限校验 + Hook安全校验链路
    - 不满足：阻断MR

### 6.3 数据写操作控制
- [ ] Agent/LLM不会自动执行数据库写操作（INSERT/UPDATE/DELETE/ALTER/DROP）
- [ ] 所有变更类写操作必须人工二次确认，系统禁止静默自动写库
- [ ] 本业务仅允许只读查询，无自动写数据逻辑
    - 不满足：阻断MR

### 6.4 安全规则防篡改
- [ ] 白名单、黑名单、拦截规则、Skill开关、权限策略为静态运维配置
- [ ] 用户Prompt、LLM输出、工具参数**不能动态修改黑白名单/安全策略**，不存在提示注入修改安全规则的入口
    - 不满足：阻断MR

### 6.5 Mock逻辑管控
- [ ] Mock接口、Mock数据仅存在单元测试/本地开发代码
- [ ] 生产分支代码**不存在Mock核心业务、安全校验、数据库能力**的逻辑
- [ ] 不存在依靠Mock通过测试、掩盖真实缺陷的情况
    - 不满足：阻断MR

> 补充：单元测试允许Mock；上线前必须移除生产环境Mock开关。

## 7. 权限与访问控制检查
- [ ] 接口访问鉴权，未登录用户不可访问Agent能力
- [ ] 数据访问做行级权限隔离，A用户不能查询B用户私有数据
- [ ] 运维配置、黑白名单变更，需要双人审批、操作审计

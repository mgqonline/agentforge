# 模型路由 (Model Routing) 入门

## 1. 什么是模型路由？为什么需要它？

在企业级 AI 应用落地的过程中，**“成本 (Cost)”**和**“延迟 (Latency)”**是两座绕不过去的大山。
如果我们把所有的用户请求都发给当前最强大的模型（如 GPT-4o、Claude 3.5 Sonnet 等），虽然效果好，但会面临两个致命问题：
1. **API 费用极其昂贵**。
2. **响应速度相对较慢**。

**模型路由**的本质，就是实现**“杀鸡不用牛刀”**：
*   **简单请求走小模型**：日常的打招呼、闲聊、基础翻译、简单的信息抽取。小模型（如 GPT-4o-mini、DeepSeek-V3 等）速度极快，且成本可能只有大模型的 1/30 甚至更低。
*   **复杂请求走大模型**：涉及多步逻辑推理、长文本深度分析、写复杂代码。这种时候必须调用大模型，用高成本换取高准确率。

## 2. 常见的路由策略

在我们的演示代码 `router_demo.py` 中，我们实现了一个最基础的路由器。工业界通常有以下几种路由进阶策略：

### A. 启发式规则路由 (Rule-based Routing)
*   **字数统计**：Prompt 长度 < 50 字走小模型，大于 50 字走大模型。
*   **关键词匹配**：检测到请求中包含 `分析`, `总结`, `代码`, `财报` 等强逻辑词汇时，直接路由给大模型。
*   *优点*：0 延迟，0 额外成本。
*   *缺点*：容易误判（比如“用一句话分析一下天为什么是蓝色的”，字数少但可能需要点推理）。

### B. 小模型/分类器前置路由 (LLM as a Router)
*   让一个小模型（甚至是一个极小的经过微调的 BERT 文本分类模型）作为“前台分诊护士”。
*   所有请求先给“小模型”看一眼，小模型输出 `SIMPLE` 或 `COMPLEX`。然后再根据它的分类，决定是否将原始请求转发给大模型。
*   *优点*：准确率大幅提升。
*   *缺点*：无论如何都会增加一次前置调用的延迟（几十到几百毫秒）。

### C. 语义路由 (Semantic Routing)
*   通过向量数据库（Embedding），把常见的“简单问题”向量化存储。
*   新请求进来时，先去向量库搜索，如果匹配到了“简单闲聊”的聚类簇，就走小模型。

## 3. 实战演示

运行演示脚本：
```bash
python 01-prompt-engineering/model_routing/router_demo.py
```

**你将观察到：**
1. 当你发送“你好”或“翻译”时，路由器识别为简单任务，将其直接分配给小模型，成本倍率为 1x。
2. 当你发送长段的“财报分析”时，路由器拦截到了复杂意图，将其分配给大模型，并可能在后台自动拼接了 CoT（思维链）提示词以增强大模型的表现，但其成本倍率是高昂的 30x。

这正是搭建**高可用、低成本** AI 系统的基石。

# 中间件、数据库与 RPC 核心技术全景

## 1. 关系型数据库：MySQL 深度剖析

### 1.1 存储引擎：InnoDB
- MySQL 默认且最常用的存储引擎。
- 支持**事务（ACID）**、**行级锁（Row-level locking）** 和 **外键约束**。
- 采用 **聚簇索引（Clustered Index）**，即数据行和相邻的键值存放在同一个 B+ 树节点中。主键查询极快，但非主键查询（辅助索引）需要先查出主键，再“回表”查询实际数据。

### 1.2 索引结构 (B+ Tree)
- 为什么不用二叉树或 Hash？Hash 不支持范围查询 (`>` 或 `<`)；二叉树在数据量大时树层级太深，导致磁盘 I/O 次数过多。
- **B+树特点**：非叶子节点只存储索引，所有数据记录都存放在叶子节点，且叶子节点通过双向链表连接。极大地减少了磁盘 I/O 层数，并完美支持排序和范围扫描。

### 1.3 事务隔离级别与 MVCC
- **四种隔离级别**：读未提交 (Read Uncommitted)、读已提交 (Read Committed)、可重复读 (Repeatable Read, **MySQL 默认**)、串行化 (Serializable)。
- **MVCC (多版本并发控制)**：InnoDB 实现“读已提交”和“可重复读”的核心机制。通过在每行数据后面隐藏的两列（事务 ID 和 回滚指针）结合 Undo Log 实现。使得**“读不加锁，读写不冲突”**，大大提高了数据库的高并发性能。

## 2. 缓存数据库：Redis

### 2.1 核心数据结构与应用场景
- **String（字符串）**：最基本类型，适用于验证码、分布式锁（`SETNX`）、计数器（`INCR`，如点赞数）。
- **Hash（哈希）**：键值对集合，非常适合存储对象（如用户详情信息 `user:1001 name age`），避免大字符串序列化。
- **List（列表）**：双向链表，适用于实现消息队列、最新动态时间线。
- **Set（集合）**：无序去重，适用于标签、交集/并集计算（如共同好友）。
- **ZSet（有序集合）**：带权重的去重集合，跳表（SkipList）实现。非常适合**排行榜**（Top 100 玩家、热搜榜）。

### 2.2 持久化机制
- **RDB (Redis Database)**：定时生成内存快照（Snapshot）。恢复速度极快，但宕机会丢失最后一次快照后的数据。
- **AOF (Append Only File)**：以日志形式记录每次写命令。数据最安全（最多丢 1 秒数据），但文件体积大，恢复慢。
- **混合持久化**（Redis 4.0 引入）：RDB 做全量基准，AOF 做增量日志，两者结合。

## 3. 高并发缓存 (Cache) 的三大经典问题

### 3.1 缓存穿透 (Cache Penetration)
- **定义**：查询一个**数据库中绝对不存在**的数据。缓存中没有，导致请求直接穿透到数据库，恶意攻击时会导致数据库直接崩溃。
- **解决**：
  1. 缓存空对象（将空值写进 Redis 并设置极短的过期时间）。
  2. **布隆过滤器 (Bloom Filter)**：在前置拦截，利用极小内存判断 key 是否存在。

### 3.2 缓存击穿 (Cache Breakdown)
- **定义**：某个极度热点的 Key（如秒杀商品）在**缓存过期的瞬间**，伴随着海量并发请求打进来，导致数据库瞬间被压垮。
- **解决**：
  1. 热点数据设置“永不过期”。
  2. 使用**分布式锁 (Mutex Key)**：发现缓存失效后，只能有一个线程拿到锁去查数据库重建缓存，其他线程挂起等待。

### 3.3 缓存雪崩 (Cache Avalanche)
- **定义**：**大量缓存同一时间集体失效**，或者 Redis 直接宕机，导致所有流量倾泻到后端数据库。
- **解决**：
  1. 在过期时间上加上一个随机数，防止集体失效（例如 `expire_time + random(1, 10)分钟`）。
  2. 搭建 Redis 高可用集群（哨兵模式 Sentinel 或 Cluster）。

## 4. 高性能 RPC 与序列化：Protobuf

### 4.1 什么是 Protobuf (Protocol Buffers)
由 Google 开发的一种语言无关、平台无关的**序列化数据结构**协议，主要用于微服务间的 RPC（如 gRPC）通信。

### 4.2 为什么比 JSON 强？
- **体积小**：JSON 带有大量繁杂的引号、括号及字段名。Protobuf 使用二进制编码（Varint 变长整数编码、Tag-Length-Value 结构），体积往往只有 JSON 的 1/3 到 1/10。
- **速度快**：JSON 需要耗时的词法/语法解析；Protobuf 基于底层二进制偏移量进行解析，序列化/反序列化速度极快，适合网络高并发密集型应用。
- **强类型防坑**：采用 `.proto` 文件作为接口契约（IDL），强制定义字段类型和编号，自动生成多语言（Java/Go/Python）代码。上下游接口变更时（如增减字段），能够实现极好的向后兼容性，彻底杜绝 JSON 中因类型错乱导致的运行时报错。

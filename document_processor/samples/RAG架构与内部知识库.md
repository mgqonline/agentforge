# RAG 架构与内部知识库

## 1. 什么是 RAG？
RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合了**信息检索技术**和**大语言模型生成能力**的复合架构。
其核心思想是：不强求大模型“记住”所有的企业私有知识，而是让大模型在回答问题前，先去企业的知识库中“开卷考试”。

## 2. RAG 的核心工作流
1. **知识库构建 (Indexing)**：
   - 将企业内部文档（PDF、Word、Markdown 等）进行解析。
   - 对长文档进行切分（Chunking）。
   - 使用 Embedding 模型将切分后的文本转化为高维向量（向量化）。
   - 存入向量数据库（如 Chroma、Pinecone 或 PostgreSQL pgvector）。
2. **知识检索 (Retrieval)**：
   - 接收用户的自然语言提问。
   - 将问题向量化，并在向量数据库中搜索最相似的若干个文档切片（Chunks）。
   - （进阶）结合传统的基于词频的检索（如 BM25），实现**混合检索 (Hybrid Search)**，提高召回率。
3. **增强生成 (Generation)**：
   - 将检索到的知识切片与原始问题组装成一个完整的 Prompt，发给大语言模型。
   - 模型基于提供的参考资料生成准确、客观的回答，并附带引用来源（Citations）。

## 3. 如何使用 RAG 构建内部知识库？
在构建内部知识库时，关键在于**数据质量和检索精度**：
- 必须清理非结构化数据中的噪音。
- 使用语义分块（Semantic Chunking）而不是简单的按字数截断。
- 采用重排模型（Reranker）对检索出的结果进行二次排序，确保喂给大模型的知识是最相关的前 K 个。

## 总结
RAG 是目前大模型落地企业最成熟、最可靠的方案，它能有效解决 AI 幻觉问题，并保证企业数据不出域。

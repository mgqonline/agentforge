# 创建需求迭代

## 必填信息

执行前必须取得 `迭代版本名称`。

- 如果用户未提供 `迭代版本名称`，先提示：`迭代版本名称 必填`，并等待用户补充。
- 不要在名称缺失时创建目录。
- 目录名中的 `迭代版本名称` 不得包含 Windows 非法路径字符：`< > : " / \ | ? *`。

## 目录规则

执行前必须先取得用户输入的 `工作目录`，并使用该目录作为需求迭代工作区根目录；若用户未提供，提示 `工作目录 必填` 并等待用户补充。

1. 若 `工作目录` 为空、不存在、不是仓库一级相对目录、包含 `..` 或多级路径，提示用户确认当前工作目录并暂停流程。
2. 扫描 `{工作目录}` 根目录下符合 `P[0-9][0-9][0-9]-*` 的目录。
3. 若没有匹配目录，新版本编号为 `P001`。
4. 若已有匹配目录，取最大编号加 1，并补足三位，例如 `P003-*` 后创建 `P004-[迭代版本名称]`。
5. 新迭代目录命名为 `Pxxx-[迭代版本名称]`。

## 创建结构

在新迭代目录下创建：

```text
Pxxx-[迭代版本名称]/
├── Pxxx-[迭代版本名称].md
├── 需求分析/
└── 需求规格/
```

## 初始计划文件

创建新迭代目录时，必须同步创建根目录计划文件 `{当前迭代目录}/{当前迭代目录名}.md`，例如 `P001-AI核心模块/P001-AI核心模块.md`。

`{当前迭代目录名}.md` 模板内容如下：

```markdown
# Pxxx-[迭代版本名称]

| 模块 | 功能点 | 功能说明 | 需求类型 | 影响范围 | 更新时间 |
| --- | --- | --- | --- | --- | --- |
```

## 执行流程

1. 校验 `迭代版本名称` 是否存在且不含非法路径字符。
2. 取得并校验 `工作目录`，定位工作区根目录。
3. 计算下一个 `Pxxx` 编号。
4. 创建 `{工作目录}/Pxxx-[迭代版本名称]`。
5. 创建 `需求分析`、`需求规格` 两个子目录。
6. 在新迭代根目录下创建 `Pxxx-[迭代版本名称].md`，并写入初始计划文件模板。
7. 完成后确认新目录路径，并列出已创建的子目录和根目录计划文件。

# 视频 RAG (Video RAG) 与时序检索原理

视频是信息的“终极载体”，它结合了图像、音频和时间。要让 Agent 能够“检索视频”，我们需要将其打碎成多个维度。

---

## 1. 核心流程：三位一体的索引

### A. 视觉维度 (Visual) - 关键帧提取
视频本质上是快速播放的照片（通常 24-60 帧/秒）。我们不需要处理每一帧，而是提取**关键帧 (Keyframes)**。
- **技术实现**: 
  - 使用 `OpenCV` 或 `FFmpeg`。
  - **采样策略**: 
    - *固定频率*: 每 5 秒截一张图。
    - *场景检测*: 检测画面突变（如从幻灯片 A 切换到幻灯片 B）时截图。
- **语义化**: 每一张截图都会通过 Vision LLM（如 GPT-4V）生成一段描述。
  - *输出*: "时间 [00:15]: 讲师正在演示如何在终端输入命令。"

### B. 听觉维度 (Audio) - ASR 转录
音频包含了大部分的信息细节。
- **技术实现**: 使用 `OpenAI Whisper` 模型。
- **时序关联**: ASR 输出不仅有文字，还有**带有起始和结束时间戳的片段 (Chunks with Timestamps)**。
  - *输出*: "[00:12 - 00:18]: 现在我们来配置 API Key..."

### C. 结构化维度 (Structural) - 元数据
- 关联视频 ID、标题、章节、URL 等。

---

## 2. 存储与检索逻辑

我们将上述信息存入向量数据库（如 Chroma）时，结构如下：

| 向量内容 (Embedding) | 元数据 (Metadata) |
| :--- | :--- |
| 视觉描述: "讲师演示命令行操作" | `{timestamp: 15, type: "video_frame", video_id: "v1"}` |
| ASR文本: "现在我们来配置 API Key" | `{timestamp: 12, type: "audio_segment", video_id: "v1"}` |

### 检索过程：
1. **用户提问**: "视频里在哪一步讲了配置 Key？"
2. **向量匹配**: 
   - 匹配到 ASR 文本片段。
   - 匹配到视觉描述片段。
3. **结果聚合**: 系统返回 "匹配到视频 v1 的 00:12 处"。

---

## 3. 时序重构 (Temporal Reasoning) - 最难的部分

单点检索只能找到“那一秒”，但 Agent 需要理解上下文。
- **滑窗检索 (Sliding Window)**: 检索到第 15 秒后，自动取出第 10 秒到第 20 秒的所有描述，发给 LLM。
- **跨模态校对**: 如果 ASR 说的是“这里”，Agent 需要看同一秒的视觉描述才知道“这里”指的是屏幕上的哪个按钮。

---

## 4. 进阶课题：长视频处理
- **分级摘要**: 
  - Level 1: 整个视频的 500 字总结。
  - Level 2: 每一分钟的小结。
  - Level 3: 原始的关键帧和 ASR。
- Agent 先搜 Level 1 定位大范围，再搜 Level 3 定位具体秒数。

---

## 总结：如何构建一个“视频教程助理”？
1. **FFmpeg** 提取关键帧 + **Whisper** 转文字。
2. **Vision LLM** 描述关键帧。
3. **Chroma** 存储带时间戳的向量。
4. **Agent** 接收问题 -> 检索时间戳 -> 给出答案并附带“点击跳转”链接。

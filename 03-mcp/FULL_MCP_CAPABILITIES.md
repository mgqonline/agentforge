# 独立开发 MCP Server 的核心：掌握“资源、工具、提示词”三位一体

MCP (Model Context Protocol) 之所以能成为统领本地 AI 应用的神器，就在于它极其优雅地对大模型所需的**上下文**进行了分类。

一个标准的 MCP Server 可以挂载以下三类能力，这就好比我们为大模型配置了**书库（Resources）**、**手脚（Tools）** 和 **锦囊（Prompts）**。

## 1. Resources (资源能力) —— 大模型的“书库”
*   **定位**：只读的数据提供者。
*   **核心特性**：
    *   通过 `URI` 标识（例如 `file:///etc/hosts`, `postgres://db/schema`, `api://github/issues`）。
    *   大模型可以主动请求读取这些 URI 的内容，将其放入自己的上下文（Context）中作为背景知识。
*   **适用场景**：暴露系统日志、公司 API 文档、数据库表结构。这些东西往往文字量巨大，且不需要模型去修改它。

## 2. Tools (工具能力) —— 大模型的“手脚”
*   **定位**：可被模型主动调用的可执行函数。
*   **核心特性**：
    *   具有**副作用（Side Effects）**。它不仅仅是用来获取信息的，而是用来改变世界状态的。
    *   模型必须提供严格的参数（通常结合 Pydantic 约束）才能调用。
*   **适用场景**：发送邮件、重启服务器、执行 SQL 增删改、控制智能家居关灯。

## 3. Prompts (提示词能力) —— 大模型的“锦囊”
*   **定位**：服务端预设的高级提示词模板。
*   **核心特性**：
    *   它是由**人类用户主动在客户端（如 Claude Desktop）点击触发**的，而不是模型自己调用的。
    *   它可以极大地方便用户。用户不需要去背诵复杂的背景知识，MCP Server 开发者已经把最好的 Prompt 写在服务器里了。
*   **适用场景**：
    *   比如在代码库的 MCP Server 中写一个 Prompt：`"Review当前修改的代码并严格遵循公司的PEP8标准"`。
    *   由于 Prompt 是由服务器生成的，所以服务器可以在 Prompt 字符串里自动混入当前系统的最新状态或强制大模型去查阅特定的 Resource。

---

## 三者的完美融合（以 `04_full_mcp_server.py` 为例）

在我们编写的 IT 运维机器人代码中，这三种能力打出了一套完美的配合连招：

1. 当系统崩溃时，人类用户很着急，他不需要自己去构思怎么提问，直接在 UI 上调用服务器提供的 **Prompt 锦囊 (`troubleshoot_service`)**。
2. 这个 Prompt 发给大模型后，大模型读到了里面系统留给它的**硬性指令**。
3. 大模型遵照指令，立刻去调用 **Resource (`log://order/latest`)** 阅读了长篇大论的报错日志。
4. 大模型通过大语言模型的推理想象力，判断这个报错是死锁。
5. 大模型果断调用 **Tool (`restart_service`)**，把服务器重启了，修复了故障。

掌握这三个维度的开发，你就能将企业内部任何复杂的孤岛系统，无缝转变为极度强大的 AI 智能体基础设施！

# 企业级 RAG 全链路工程架构白皮书

在普通的教程中，RAG 往往被简化为：`读文件 -> 瞎切一通 -> 存向量 -> 搜向量 -> 提问`。这种被称为 **Naive RAG (天真 RAG)**，在真实企业落地中准确率通常**不到 60%**，回答全靠运气，甚至频发灾难性幻觉。

通过整合本项目 `04-rag` 目录下的所有战术，我们构建出了一套**准确率高达 90%+ 的工业级 Advanced RAG 架构**。

---

## 一、 全链路架构执行步骤解剖

结合代码 `enterprise_rag_pipeline.py`，我们的生产管线分为五道绝对防线：

1. **多模态清洗摄入 (Ingestion)**
   * **动作**：针对 PDF 提取文本块，针对 Excel `df.to_markdown()`。
   * **价值**：将一切不可读的二维结构表格，全部拍扁为大模型最容易读懂的 Markdown 一维字符。
2. **结构感知切分 (Structure-Aware Chunking)**
   * **动作**：弃用按字数强切，改用 `MarkdownHeaderTextSplitter`。
   * **价值**：表格绝不会被拦腰砍断，章节标题（如“2.算力采购”）会被永远烙印在文本块的 Metadata 中。大模型读到碎片时，自带上帝视角的篇章记忆。
3. **双引擎并发召回 (Dual-Engine Recall)**
   * **动作**：同时派发 `FAISS` (向量/稠密) 和 `BM25` (词频/稀疏) 去百万库里各捞取 Top 50。
   * **价值**：FAISS 捕捉用户的“口语化隐喻”，BM25 捕捉极度专业的“日志代码/专有订单号”。一张网捞不全的，两张网互补。
4. **倒数秩融合排序 (RRF Fusion)**
   * **动作**：用 $1 / (k + Rank)$ 的数学公式，把两边捞回来的 100 篇文档无缝融合排序。
   * **价值**：极优雅地统一了“相似度”和“词频”两种不同的单位，找出两份榜单上的真正“常委”。
5. **交叉编码器精排 (Cross-Encoder Rerank)**
   * **动作**：用带有注意力机制的小型语言模型（如 `bge-reranker`），对这 100 篇嫌疑文档进行“用户问题 vs 文档内容”的逐字对齐审判，最终掐尖选出 Top 3。
   * **价值**：彻底消除“字面沾边但逻辑不通”的垃圾文档。喂给 LLM 的都是绝对纯净的真金白银。

## 二、 核心顽疾与终极解决方案

在从 60% 向 90% 的攀峰过程中，企业往往会遇到以下三大死穴。我们的工程架构已经将其全部化解：

### 顽疾 1：迷失在中间 (Lost in the Middle) 现象
* **问题**：如果你一口气召回了 20 篇文档喂给大模型，大模型的“金鱼记忆”会导致它极度关注最上面和最下面的文档，而把排在中间的救命答案直接遗忘。
* **解决方案**：引入 **Rerank 精排防线**。极度苛刻地把 `top_k` 从 20 压榨到 **Top 3 甚至是 Top 1**。只要送进去的粮草足够少且足够精，大模型就绝不会迷失。

### 顽疾 2：极其严重的表格幻觉 (Table Hallucination)
* **问题**：用 PyPDF 等基础包读 PDF 里的财报表格，读出来的字全是一坨散沙。大模型根本不知道第三行的数字对应的表头是什么。
* **解决方案**：源头治理。不要指望大模型，必须在上游（如 `document_parsing_pipeline.py` 中）接入强大的版面分析（Layout Analysis）或多模态 OCR，提取为严格的 **Markdown Table**。一旦转成了 Markdown `|...|...|` 结构，幻觉率将暴降。

### 顽疾 3：长尾词与 UUID 的灾难
* **问题**：用户搜索 `Session_ID: 9Xz2_0A`，结果 Embedding 模型没见过这串字符，把它解析成乱码，召回了一堆八竿子打不着的文档。
* **解决方案**：双路架构中的 **BM25 引擎**是解决此问题的绝对王牌。TF-IDF 机制对这种长尾乱码词极其敏感，会瞬间将其锁定并提到榜首。

# RAG 高阶文本切块策略 (Advanced Chunking)

在熟悉了递归字符切分和 Markdown 结构切分后，在企业级生产环境中，我们往往还需要应对极端场景（如极度严格的 Token 限制，或者毫无排版结构的口水话文本）。这就需要引入**滑动窗口**与**语义切分**。

## 三、 Token 级滑动窗口切分 (Sliding Window Token Splitting)

在 `advanced_chunking_demo.py` 中，我们使用了 `TokenTextSplitter`。

### 1. 核心技术痛点：字符 $\neq$ Token
大模型 API 计费和上下文限制都是基于 `Token` 的。如果你按字符切分（比如每块 1000 字符），遇到全是复杂生僻字的代码或图纸，它可能会被底层分词器解析成 2000 个 Token，导致直接把模型的 Context 撑爆报错。

### 2. 滑动窗口操作方案
* **Token 化**：调用与底层大模型（如 OpenAI）完全一致的 `tiktoken` 库，先将全文转化为 Token 数组。
* **滑动步长 (Stride / Overlap)**：
  设定窗口大小为 $N$ (如 500 Tokens)，滑动步长为 $S$ (如 250 Tokens)。
  - 窗口 1：包含全文的第 0 到 500 个 Token。
  - 窗口 2：向右滑动 $S$。包含全文的第 250 到 750 个 Token。
  - 窗口 3：包含全文的第 500 到 1000 个 Token。
* **优势**：
  1. 绝对的容量安全：丢给大模型的内容永远不会超过 $N$ 个 Token。
  2. 上下文无死角：因为重叠区达到了 50%，任何一个关键信息点，都至少会完整存在于某一个完整窗口的最中央，从而极大提高了向量召回的命中率。

## 四、 语义切分 (Semantic Chunking) 

这是目前业界最前沿（State of the Art）的无结构文本切分方案，它由 LlamaIndex 最早发扬光大，目前 Langchain 在其 `experimental` 包中提供了支持。

### 1. 核心痛点：标点符号不代表语义逻辑
递归切分只能死板地看 `\n\n` 来切。但如果用户上传的是一篇长长的访谈语音转录文本（Audio Transcript），里面全是没头没尾的短句，根本没有换行符和章节名，传统的切分会把同一个问题的上下半句硬生生切开。

### 2. 语义断层切割方案 (Semantic Shift)
* **步骤一：单句向量化**
  利用诸如 `NLTK` 或 `Spacy` 先把文章切成最细粒度的单个句子。然后将**每一句话**单独喂给 Embedding 模型，获得一个 1536 维的向量。
* **步骤二：计算余弦相似度瀑布图**
  计算第 1 句话与第 2 句话的相似度（比如 0.92），第 2 句与第 3 句的相似度（0.91）。
* **步骤三：寻找断崖下跌点 (Thresholding)**
  当计算到第 5 句话（“今天天气很好”）与第 6 句话（“根据量子力学公式”）时，相似度突然暴跌到 0.15。
  此时，切分器就会判定：**这里发生了话题转移（Topic Shift）！** 于是果断在第 5 句话和第 6 句话之间狠狠切下一刀。
* **优势**：
  切出来的每一块碎片，长度可能大相径庭（有的 100 字，有的 1000 字），但**每一块碎片内部都保持着绝对纯粹的独立语义主题**。这对于向量检索来说简直是降维打击级别的增强！
